## 4. 建集合（云数据库）

云开发控制台 → 数据库 → 新建集合，**Day1–3 只需 2 个**：

| 集合名 | 用途 | 本阶段权限建议 |
| --- | --- | --- |
| `users` | 用户档案 | **仅创建者可读写**（或自定义安全规则，见下） |
| `stalls` | 摊位 | **所有用户可读，仅创建者可写**（顾客端 Day6 要读） |

> Day4 起会再加 `products`、`orders` 等，本次先建这两个。

### 权限设置（控制台「数据权限」）
- `users`：选「仅创建者可读写」即可（用户只动自己的档案）。
- `stalls`：选「所有用户可读，仅创建者可写」。
  - 但注意：**云函数走的是 admin 权限，绕过这些规则**，所以即便严格设置也不影响云函数读写。前端如果直接 `db.collection().get()` 才受规则约束。本项目所有读写都走云函数，权限可从严。

### 推荐：两个集合都用云函数读写，权限设为「仅管理端」
若想最严格：数据权限选「仅管理端可读写（自定义安全规则 `false`）」，所有访问强制走云函数。本项目架构正是如此，**推荐这个**。

## 5. 真机/模拟器联调验收

### 5.1 echo 连通性（最先验证）
在任意页面临时调用，或用工具「云开发 → 云函数 → echo → 云端测试」，传 `{"hello":"taner"}`，期望返回：
```json
{ "code": 0, "message": "ok", "data": { "echo": {...}, "openid": "o...", "serverTime": 1719... } }
```
✅ 能拿到 `openid` 说明云开发链路通了。

### 5.2 登录闭环
1. 打开小程序 → 「我的」页 → 点「点击登录」
2. 授权头像昵称（或拒绝走静默登录）
3. 期望：
   - `users` 集合新增一条记录（openid / role=customer / hasStall=false）
   - 「我的」页显示昵称 + 角色标签
4. 二次进入：不重复建档，仅更新 `lastLoginAt`

### 5.3 双角色切换
- 「我的」页点「切换到摊主身份」→ 菜单变为摊主菜单（摊位设置/商品管理…）
- 角色持久化：杀进程重进仍是上次角色

### 5.4 开店闭环
1. 摊主身份 → 「摊位设置」
2. 填名称、选品类、点地图选点、填时段 → 「立即开店」
3. 期望：
   - `stalls` 新增记录，`userId` = 当前用户 `_id`
   - `users` 对应记录 `hasStall` 变 `true`、`role` 变 `seller`
   - 再次进入「摊位设置」是编辑模式（回填表单）
4. 一人一摊：再点开店应提示「您已开店」

## 6. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Taro.cloud 不存在` / 初始化失败 | 基础库 < 2.2.3 或未开通云开发 | 升基础库；确认已开通 |
| 云函数调用 `-501000` | 云函数未部署或名字不符 | 确认 3 个函数都「上传并部署」 |
| `openid` 为空 | 工具未登录微信 / 模拟器限制 | 用真机预览，或工具右上角登录微信 |
| 读集合返回空但库里有数据 | 前端直读受权限规则限制 | 本项目都走云函数，确认调的是云函数而非 `db.collection` |
| 开店成功但顾客端看不到 | 权限或 `status=offline` | Day6 再联调；`nearby` 已过滤 offline |
