# 地摊小微商户线上小店小程序 - 两周开发计划（单人全栈 / 完整 P1 MVP）

> 目标：14 个自然日内，单人全栈交付**可上线的 P1 MVP**
> 技术栈：Taro 3.x + React18 + TS（复用现有原型）/ 微信云开发 CloudBase（云函数 + 云数据库 + 云存储）
> 配套：[架构设计文档](./地摊小微商户线上小店小程序-架构设计文档.md) ｜ [数据库设计文档](./地摊小微商户线上小店小程序-数据库设计文档.md)

---

## 〇、定位与现实预期（先读这一段）

单人两周交付完整 P1 是**极限排期**，能成功的前提是：**砍掉一切非闭环功能、用最省事的技术方案、严格按天验收、出现延期立即触发降级**。本计划已据此做了取舍。

### 关键决策

| 决策项 | 选择 | 理由 |
| ------ | ---- | ---- |
| 后端 | **微信云开发 CloudBase** | 单人两周免运维、免鉴权、免备案、登录/存储/DB 开箱即用 |
| 数据存储 | CloudBase **云数据库（文档型集合）** | 集合字段对齐《数据库设计文档》P1 表；省去建表/连接/ORM |
| 前端 | Taro 复用现有 React 原型 | 原型逻辑/组件可大量迁移，节省 UI 时间 |
| 在线支付 | **P1 不做线上支付，改"线下自提付款"** | 微信支付需企业资质 + 数天审核，规避卡点（见下方风险） |
| AI 语音 | 微信同声传译插件（ASR）+ LLM 意图解析，**只做 4 个意图** | 控制范围，保留差异化亮点 |
| AI 定价 | 规则计算为主 + LLM 生成话术（可选） | 不依赖模型也能出结果，稳 |

### 🔴 上线前必须知道的硬约束

1. **微信支付**：个人主体小程序无法开通；企业主体申请 + 审核需 3-7 天。→ P1 用线下付款规避，**不阻塞两周计划**。若已有企业资质和支付商户号，可在 Day 8 插入线上支付（约 +1 天）。
2. **小程序类目与资质**：电商/到店类目可能需要营业执照、《增值电信》或行业资质，**审核 1-7 天**。→ Day 1 立即提交主体注册和类目申请，与开发并行。
3. **地理位置接口**：`getLocation`/附近的小程序需在 mp 后台填写"接口使用说明"并通过审核。→ Day 1 一并申请。
4. **UGC 内容安全**：打卡/许愿等用户内容必须接 `security.msgSecCheck` 文本检测、`imgSecCheck` 图片检测，否则审核驳回。→ 已纳入 Day 10。
5. **LLM API**：DeepSeek / 通义千问 Key 需提前申请，配置到云函数环境变量。→ Day 1 准备。

### ✂️ 降级线（延期时按此顺序砍）

> 任何一天 delay，优先砍下列功能，保证"核心闭环可演示可上线"不动摇：
> AI语音助手 → 大字极简模式 → 优惠券 → 许愿池 → 聚合码 → 拼团（本就不在P1）
> **绝不可砍的最小可上线集**：微信登录 → 开店 → 商品管理 → 顾客地图/详情 → 预定下单 → 摊主接单 → 自提核销。

## 二、14 天逐日计划

> 每天结构：**任务 → 交付物 → 验收标准**。涉及的集合/接口对齐两份设计文档。
> 建议节奏：上午后端云函数 + 数据，下午前端页面联调；每晚真机自测当日交付物。

### 🟩 阶段一：地基（Day 1-3）

#### Day 1 — 账号、环境、脚手架（关键并行启动日）
**任务**
- 行政并行（与开发同步进行，不占编码时间）：
  - 注册/确认小程序主体，提交**类目申请**（电商-商家自营 / 餐饮 等）
  - mp 后台申请 `getLocation`、附近的小程序、`subscribeMessage` 权限说明
  - 申请 LLM API Key（DeepSeek / 通义千问）
  - 开通微信云开发 CloudBase，创建环境（test / prod）
- 编码：
  - Taro 项目初始化（TS + React18 + NutUI），接通 CloudBase SDK
  - 配置分包结构（customer / seller 两个分包）
  - 搭建 `request` 封装（统一调云函数）、Zustand stores 骨架
  - 在 CloudBase 建 P1 集合：`users` `stalls` `products` `orders` `coupons` `wishes` `stall_qrcodes`（字段对齐数据库文档）

**交付物**：可运行的 Taro 空壳 + CloudBase 连通 + 集合就绪
**验收**：真机打开小程序，能调用一个 echo 云函数返回数据

#### Day 2 — 微信登录 + 用户体系 + 角色切换
**任务**
- 云函数 `login`：`getWXContext` 取 openid → upsert `users` → 返回用户态
- 前端 `userStore`：登录态持久化、`role` 切换（customer/seller）
- "我的"页基础框架（顾客端 + 摊主端）

**交付物**：登录闭环、双角色切换
**验收**：新用户首次进入自动建档；可在顾客/摊主身份间切换

#### Day 3 — 30秒极速开店 + 摊位管理
**任务**
- 云函数 `stall.create / stall.update / stall.get`
- 开店表单：名称、品类、点位（`chooseLocation` 取经纬度）、出摊时间
- 出摊/歇业一键切换（`stall.updateStatus`）
- 摊主端"摊位设置"页

**交付物**：摊主可开店、编辑、切换出摊状态
**验收**：开店流程 ≤30 秒可走完；状态切换实时生效

---

### 🟦 阶段二：商品与摊主核心（Day 4-5）

#### Day 4 — 商品管理 + 图片上传
**任务**
- 云存储图片上传 hook（`Taro.chooseImage` → `uploadFile`）
- 云函数 `product.create/update/delete/list`，上下架 `status`
- 商品列表 + 新增/编辑表单（迁移自 SellerApp 原型）
- 库存、标签、清仓标记

**交付物**：商品全生命周期管理
**验收**：可增删改商品、上传图片、上下架，顾客端能看到变化

#### Day 5 — AI 定价助手
**任务**
- 云函数 `ai.pricing`：输入成本/同行价/摊位费/品类 → 规则计算建议价、引流价、清仓价、溢价、毛利率、保本销量；写 `pricing_records`
- （可选）调 LLM 生成一句定价说明
- 定价页 UI（迁移自原型 PricingPage），一键回填到商品

**交付物**：AI 定价建议 + 利润测算
**验收**：输入成本即得多档价格与保本销量，可一键应用到商品

### 🟪 阶段三：顾客端浏览（Day 6-7）

#### Day 6 — 顾客地图首页
**任务**
- 云函数 `stall.nearby`：按经纬度范围 + 品类筛选，应用层算距离排序
- 地图组件（`Map` 组件 + `cover-view` 标记），出摊状态色标（出摊中/即将/已收摊）
- 品类筛选、摊位简略卡片列表
- 底部导航（地图/小店/广场/我的）

**交付物**：地图可视化 + 附近摊位
**验收**：地图显示在线摊位，可按距离/品类筛选，点标记弹卡片

#### Day 7 — 摊位详情 + 商品浏览
**任务**
- 摊位详情页：实景图（原图/AI优化对比切换）、商品列表、摊位信息、出摊状态、公告
- 商品详情/预定入口
- 优惠券区、许愿区占位（Day 8-10 填充）

**交付物**：完整摊位详情浏览
**验收**：从地图进店，浏览商品、看实景对比、看出摊状态

### 🟧 阶段四：交易闭环（Day 8-9）核心中的核心

#### Day 8 — 预定下单 + 取货码
**任务**
- 云函数 `order.reserve`：创建预定单（`type=reserve`）、生成 `pickup_code`、库存预扣（事务/原子更新）、写 `inventory_logs`
- 预定流程：选商品 → 填取货时间/备注 → 选券（可选）→ 提交 → 取货码票据
- （企业主体可选插入：微信支付下单 + 回调，约 +1 天）

**交付物**：顾客预定 → 取货码生成
**验收**：下单成功扣库存、生成唯一取货码、推送摊主新订单

#### Day 9 — 摊主订单管理 + 自提核销
**任务**
- 云函数 `order.list / order.confirm / order.complete / order.cancel`
- 摊主订单页：待处理/已确认/已完成 Tab，接单、排单（按时间排序）、凭码核销
- 取货码核销（顾客出示 → 摊主确认完成）
- 弃单/取消处理

**交付物**：摊主接单 → 核销完整链路
**验收**：摊主能确认订单、按码完成核销，状态全程同步顾客端

### 🟨 阶段五：营销与差异化（Day 10-12）

#### Day 10 — 优惠券 + 许愿池 + 内容安全 ✅ 已完成（2026-06-25）
**任务**
- 云函数 `coupon.create/claim/list`，`user_coupons` 领取记录，下单核销
- 云函数 `wish.create/list/reply`，摊主回复（可到货时间/预定价）
- **接入 `msgSecCheck`/`imgSecCheck`**：许愿、打卡等 UGC 文本图片检测
- 顾客领券、许愿；摊主发券、回愿

**交付物**：优惠券 + 双向许愿池
**验收**：领券下单可抵扣；许愿可提交并被摊主回复；违规内容被拦截

**✅ 实际交付（commit `7eacd3c`，`npx taro build --type weapp` 通过）**
- 云函数 `coupon`：发券 / 领券 / 列表（摊主本店、顾客可领、我的券三视角），含券名 `msgSecCheck` 文本安全检测
- 云函数 `wish`：许愿 / 列表 / 回愿 / 点赞，许愿内容与摊主回应留言均接 `msgSecCheck`
- `order` 云函数接入优惠券核销：下单校验券（归属/状态/摊位/门槛/有效期）+ 折扣计算；订单创建后**原子标记 `used`**（`where status:unused` 防并发重复抵扣，失败回滚库存+删单）；**取消订单自动退券**恢复 `unused`
- 前端 `couponStore` / `wishStore`
- 摊主：优惠券管理页（满减/折扣/赠品三类、发券、暂停/恢复）；许愿池回应（状态+留言+预定价+到货时间）
- 顾客：摊位详情页领券横滑条 + 许愿池入口；「我的优惠券」页（可用/已用/过期分 Tab）；预定页底部选券弹层（实时算折扣、显示应付/已省）；许愿与点赞
- 路由注册（customer：`my-coupons`、`wish-pool`；seller：`coupon-manage`）+「我的」页菜单入口接入
- **折扣口径约定**：折扣券 `discount` 存"折数"（如 8.5 折存 8.5），前后端抵扣计算一致；赠品券（gift）当前不产生金额抵扣，仅作领取凭证
- **暂未做**：`imgSecCheck` 图片检测（许愿/优惠券暂无用户上传图片，后续打卡功能再接）

#### Day 11 — 聚合摆摊码 + 大字极简模式
**任务**
- 云函数 `qrcode.generate`：`getUnlimited` 生成带 scene 的小程序码，存 `stall_qrcodes`
- 扫码进店路由（解析 scene → 落地摊位详情/领券）
- 大字极简模式：`uiStore.bigFontMode`，放大按钮、精简为上架/收款/提现/发券四大入口

**交付物**：聚合码 + 大字模式
**验收**：生成码可扫码进店；大字模式一键切换且可操作核心功能

#### Day 12 — AI 语音助手（高风险，做不完即降级）
**任务**
- 接入微信同声传译插件做 ASR（语音转文字）
- 云函数 `ai.voiceCommand`：LLM 解析为 4 个意图 `list_product / change_price / send_coupon / close_stall`，输出结构化参数 → 调对应业务云函数；写 `ai_voice_logs`
- 语音助手页：录音按钮、识别结果确认、执行反馈、快捷指令

**交付物**：语音完成 4 类核心操作
**验收**：说"招牌烤冷面上架12元"能创建商品草稿待确认
**⚠️ 若进度落后**：本日整体砍掉，语音入口改为"快捷指令按钮"，不阻塞上线
