# 地摊小微商户线上小店小程序 - 架构设计文档

## 一、项目概述

### 1.1 产品定位

面向零基础地摊摊主的微信小程序，打通「线下摊位引流 → 线上小店成交 → 私域复购留存 → AI辅助经营」闭环。核心差异化：完全贴合地摊流动性强、客群同城、碎片化经营、摊主零基础、低成本五大特质。

### 1.2 核心用户角色

| 角色             | 描述                           | 核心诉求                                   |
| ---------------- | ------------------------------ | ------------------------------------------ |
| 摊主（Seller）   | 地摊经营者，零基础、中老年为主 | 极简操作、AI自动经营、快速出单、低门槛     |
| 顾客（Customer） | 同城消费者                     | 发现附近地摊、线上预定、优惠领取、线下自提 |

### 1.3 现有原型基础

目前 `UI/` 目录下已有一个 React + Vite 的交互原型，实现了顾客端和摊主端的核心交互流程，可作为小程序 UI 开发的参考。

## 二、技术选型

### 2.1 小程序框架：Taro 3.x

| 维度       | 选型理由                                                     |
| ---------- | ------------------------------------------------------------ |
| 跨端能力   | 一套代码编译为微信小程序 + H5（未来可扩展支付宝/抖音小程序） |
| React 生态 | 语法与现有原型一致，组件可直接迁移                           |
| 社区活跃   | 京东维护，生态成熟，插件丰富                                 |
| TypeScript | 原生支持，类型安全                                           |

### 2.2 前端技术栈

| 技术                | 用途      | 说明                             |
| ------------------- | --------- | -------------------------------- |
| Taro 3.x + React 18 | UI 框架   | 与现有原型技术栈对齐             |
| TypeScript          | 类型安全  | 全项目统一                       |
| NutUI / Taro UI     | UI 组件库 | 小程序原生风格组件               |
| Zustand             | 状态管理  | 轻量、无 boilerplate，适配小程序 |
| SCSS Modules        | 样式方案  | Taro 原生支持                    |

### 2.3 后端技术栈

| 技术              | 用途                                   |
| ----------------- | -------------------------------------- |
| Node.js + Express | API 服务                               |
| TypeScript        | 类型安全                               |
| MySQL 8.0         | 主数据库（订单、用户、商品）           |
| Redis             | 缓存、会话、实时状态（出摊状态热数据） |
| 腾讯云 COS        | 商品图片/短视频存储                    |
| 微信云开发        | 备选方案（轻量部署）                   |

### 2.4 AI 服务

| 能力            | 方案                              |
| --------------- | --------------------------------- |
| 语音识别（ASR） | 微信同声传译插件 / 腾讯云 ASR     |
| AI 图片优化     | 腾讯云图像处理 / 服务端调用大模型 |
| AI 定价/文案    | 服务端 DeepSeek / 通义千问 API    |
| AI 客服         | 服务端 LLM + 预设知识库 RAG       |

### 2.5 小程序插件/能力

| 插件/能力           | 用途                     |
| ------------------- | ------------------------ |
| 微信支付            | 线上支付                 |
| 微信地图/附近小程序 | 地摊点位可视化、同城曝光 |
| 微信服务通知        | 出摊提醒、订单通知       |
| 小程序订阅消息      | 顾客触达                 |
| 微信同声传译        | 语音输入                 |

### 4.3 状态管理设计 (Zustand)

```typescript
// userStore - 用户身份
interface UserStore {
  user: User | null;
  role: 'customer' | 'seller';
  isLoggedIn: boolean;
  login: () => Promise<void>;
  logout: () => void;
  switchRole: () => void;
}

// stallStore - 摊位数据（核心）
interface StallStore {
  stalls: Stall[];
  currentStall: Stall | null;
  fetchStalls: (params: StallQuery) => Promise<void>;
  setCurrentStall: (id: string) => void;
  updateStatus: (status: StallStatus) => void;
}

// orderStore - 订单状态
interface OrderStore {
  orders: Order[];
  fetchOrders: (role: 'customer' | 'seller') => Promise<void>;
  createReservation: (productId: string) => Promise<void>;
  confirmOrder: (orderId: string) => void;
}

// uiStore - UI偏好
interface UIStore {
  bigFontMode: boolean;
  toggleBigFont: () => void;
  voiceEnabled: boolean;
  setVoiceEnabled: (v: boolean) => void;
}
```

## 六、数据模型设计

### 6.1 核心实体关系

```
User (用户)
  ├── 1:N ─── Stall (摊位)        # 一个摊主可有多个摊位
  ├── 1:N ─── Order (订单)        # 用户可下多个订单
  ├── 1:N ─── Wish (许愿)         # 用户可多个许愿
  └── 1:N ─── CheckIn (打卡)      # 用户可多次打卡

Stall (摊位)
  ├── 1:N ─── Product (商品)      # 摊位有多个商品
  ├── 1:N ─── Coupon (优惠券)     # 摊位发多张优惠券
  ├── 1:N ─── GroupBuy (拼团)     # 摊位发起多个拼团
  └── 1:N ─── Wish (许愿)         # 摊位收多个许愿

Order (订单)
  ├── N:1 ─── User
  ├── N:1 ─── Stall
  └── 1:N ─── OrderItem (订单项)
```

## 七、核心业务流程

### 7.1 顾客预定下单流程

```
顾客浏览地图/商品 → 选择商品 → 填写取货时间/备注
  → 选择优惠券（可选） → 提交预定
  → 生成取货码 → 推送摊主新订单通知
  → 摊主确认备货 → 顾客到摊位凭码取货 → 完成
```

### 7.2 摊主商品上架流程

```
摊主拍照/选择图片 → AI自动去背景优化
  → 语音/文字输入商品名、进价
  → AI定价建议（参考同行/成本/点位）
  → 一键确认上架 → 实时同步到顾客端
```

### 7.3 歇业保护流程

```
触发方式：手动点击 / 语音指令 / 定时自动
  → 摊位状态 → offline
  → 线上商品 → 暂停预定
  → 已有订单 → 自动发通知告知改期
  → 地图标记 → 灰色打烊中
```

## 八、非功能性设计

### 8.1 性能

- 小程序首屏加载 < 2s（分包加载）
- 地图标记懒加载，可视区域渲染
- 商品图片 CDN + WebP 格式
- Redis 缓存热门摊位数据（TTL 5分钟）

### 8.2 安全

- JWT Token + 微信 session_key 双重验证
- API 接口防重放攻击
- 支付回调签名验证
- 用户隐私数据加密存储

### 8.3 可维护性

- 组件粒度：页面 → 区块模块 → 基础组件
- 服务端模块化拆分，单一职责
- 统一错误码规范
- 接口文档自动生成（Swagger）

### 8.4 可扩展性

- 摊位品类/模板可配置扩展
- AI 服务接口抽象，可切换不同模型
- 支付渠道可扩展（先微信支付，后续支付宝等）

### 推荐方案（轻量起步）

- **服务器**：腾讯云轻量应用服务器 2C4G（约 100元/月）
- **数据库**：腾讯云 MySQL 基础版（约 50元/月）
- **Redis**：腾讯云 Redis 256MB（约 30元/月）

- **AI 服务**：DeepSeek API / 通义千问 API（按 token 计费，初期可免费额度）

> 备选方案：使用微信云开发（CloudBase），无需自建服务器，适合极低成本起步，但灵活性略低。
